# UX 改善タスク — 1日使用フィードバックより（2026-04-07）

各タスクは独立して着手できる。優先度順に並べているが、必ずしもこの順で実施しなくてよい。
各タスク完了後にビルドが通ることを確認すること。

---

## Task 1：起動時のデフォルト画面を「今日やること」に変更

**背景：** アプリ起動後にInboxが表示され、今日の作業状況を確認するまでに余分な操作が必要。

**目標：** 起動直後に「今日やること」が表示される。

**変更対象：**
- `MainNavBar.kt` または `MainWindow.kt` — 初期選択タブを `今日` に変更

**実装方針：**
- ボトムナビの初期選択インデックス（または初期ルート）を `今日` に切り替える
- タブ構成やナビゲーション構造は変えない
- 変更は1〜2行で済む想定

---

## Task 2：振り返り画面からステップを操作できるようにする

**背景：** テーマ詳細で作ったステップを振り返り画面から変更・アーカイブできない。1日の終わりに「着手した」「終わった」「もう要らない」を振り返り側で完結させたい。

**目標：** 振り返り画面の各ステップ行から、アーカイブ（完了扱い）と内容メモの編集ができる。

**変更対象：**
- `review/ReviewScreen.kt` — ステップ行にアーカイブボタン（または長押しメニュー）を追加
- `review/ReviewViewModel.kt` — ステップのステータス更新ロジックを追加
- `step/StepDao.kt` — 必要に応じて `archiveById` などのメソッドを追加

**実装方針：**
- 「完了してアーカイブ」と「着手したが未完了（翌日持ち越し）」の2操作を用意する
- UIはシンプルに。スワイプアクションかボタン行で対応
- ステップの内容（タイトル）編集は今回は対象外。アーカイブ操作のみ

---

## Task 3：今日のビューでステップタイトルを前面に出す

**背景：** 今日やることビューでタスク詳細（テーマ名・入口アクション等）がメインに表示されており、ミニマルな「最小ステップ」のタイトルが埋もれている。

**目標：** 一覧ではステップタイトルを大きく表示し、詳細はタップで展開する。

**変更対象：**
- `today/TodayScreen.kt` — タイムラインブロック・リスト行のレイアウト変更

**実装方針：**
- 一覧行：ステップタイトルを大きめのテキストで表示、テーマ名は小さくサブテキストとして
- 詳細（starterAction・テーマのゴール）はタップで展開するシートまたはセクションに移動
- 既存の詳細シートを流用してよい

---

## Task 4：ステップ・テーマ一覧の並び順をモバイル操作に合わせる

**背景：** スマホでは画面下部が指が届きやすい。最近追加したもの・重要なものが下に来ると操作しやすい可能性がある。

**目標：** ステップ一覧・テーマ一覧で、新しいものが下に並ぶ（降順 → 昇順、もしくは逆順）。

**変更対象：**
- `theme/ThemesScreen.kt` — テーマ一覧の表示順を `createdAt` 昇順に変更（古い→新しい順）
- `theme/ThemeDetailScreen.kt` — ステップ一覧も同様に昇順
- 対応するViewModelのクエリ（`ThemeDao.kt`, `StepDao.kt`）の並び順を変更

**実装方針：**
- まずステップ一覧のみ昇順に変更して使用感を確認する
- テーマ一覧は件数が増えてから検討してもよい
- Roomクエリの `ORDER BY createdAt ASC` への変更のみで済む想定

## Task 5：Inboxアイデアの分解・複数テーマ化への対応

**背景：** 実際のアイデアは複合的・抽象的なことが多く、1エントリ→1テーマへの変換が合わないケースがある。

**目標：** Inboxエントリから複数テーマを作れる、またはAI対話の中で分解できる。

**実装方針（段階的に対応）：**

### 5a：手動での複数テーマ作成（小変更）
- 現状のInbox詳細から「テーマを作成する」ボタンを複数回押せるようにする（1エントリから複数テーマを作れる）
- InboxエントリのステータスをArchived にする条件を「1つ目のテーマ作成時」→「手動でアーカイブ」に変更する

### 5b：AI対話での分解促進（Step 6実装後）
- AI立ち上げ対話のシステムプロンプトに「複合的なアイデアは複数テーマに分けることを提案してよい」旨を追加
- 対話完了時に複数のTheme + Stepを一括生成できるロジックを追加（`CoachingViewModel.kt`）

**優先度：** 5aのみ先行実装し、5bはStep 6（AI立ち上げ対話）実装時にまとめて対応

## Task 6：振り返りAI相談の結果をテーマのステップに反映する

**背景：** 振り返り画面でAIと相談しても、提案された次のステップをテーマへ追加する操作が存在しない。相談した内容が宙に浮いてしまう。

**目標：** AI対話の終了後に、提案されたステップをテーマへワンタップで追加できる。

**変更対象：**
- `review/ReviewScreen.kt` — AI対話完了後に「提案されたステップを追加する」確認UIを表示
- `coaching/CoachingViewModel.kt` — review contextType の対話完了時にStep追加ロジックを呼ぶ
- `step/StepDao.kt` — 必要に応じてinsertメソッドを確認

**実装方針：**
- AI応答の末尾にステップ提案が含まれる場合、確認ダイアログまたはボトムシートで「追加する / スキップ」を選択できるようにする
- 追加するテーマはレビュー対象と同一テーマを前提とする（複数テーマへの振り分けは後回し）
- ステップタイトルは編集してから保存できるようにする

## Task 7：翌日のステップを事前に計画できるようにする

**背景：** 「今日やること」ビューは当日分のみ表示される。仕様上は「前日の夜に翌日のステップを選ぶ」準備フローを想定しているが、そのための画面・操作がない。

**目標：** 翌日分のステップをテーマ詳細または今日ビューからスケジュールできる。

**変更対象：**
- `today/TodayScreen.kt` — 「今日 / 明日」切り替えタブ、または日付ナビゲーションを追加
- `today/TodayViewModel.kt` — 表示対象日付をパラメータ化する
- `today/StepScheduleSheet.kt` — スケジュール追加時に対象日（今日 / 明日）を選べるようにする

**実装方針：**
- まずシンプルに「今日 / 明日」の2タブ切り替えで実装する
- `ScheduledStep.date` を今日または翌日で保存できれば最小実装として成立する
- テーマ詳細の「今日やる」ボタンも「今日 / 明日やる」に選択肢を増やす（オプション）

## 実施順の推奨

| 優先度 | タスク | 理由 |
|---|---|---|
| 高 | Task 1 | 1行の変更で毎回の使い勝手が改善する |
| 高 | Task 3 | 今日のビューは毎日使う中心的な画面 |
| 高 | Task 7 | 翌日計画ができないとデイリーサイクルが回らない |
| 中 | Task 2 | 振り返りの完結性が上がる |
| 中 | Task 6 | AI相談を実装（Step 7）後にセットで対応 |
| 中 | Task 4 | 小変更だが効果は使ってみないとわからない |
| 低 | Task 5 | 設計変更を伴う。AI対話実装と合わせて検討 |
