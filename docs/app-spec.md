# アプリ仕様書 — idea-to-action

## コンセプト

個人プロジェクト・アイデアを、**着実に前進させ続ける**アプリ。

- 日常的な思いつきをInboxに投げ込み、ふとしたタイミングでテーマへ育てる
- AIがその日のステップ候補を提案する。ユーザーはポチポチ承認するだけ
- 着手することが主眼。完了できなくてもいい
- 振り返りは3択でポチポチ → AIが次のステップを更新する
- テーマが少しずつ確実に前進していることを実感できる

---

## コアフロー

```
Inbox（日常的に思いつきをポンポン投げ込む）
  ↓ ふとしたタイミングでAI対話 → 複数エントリをまとめてテーマ化
テーマ（個人プロジェクト・興味領域。上限なし）
  ↓ AIコーチング：今進めたいものを絞り込む
今日のステップ候補（AIが提案 → ユーザーが承認/調整）
  ↓ 通知が着手を促す → 着手したらマーク
振り返り（3択: できた / 着手した / できなかった）
  ↓ AIが一言フィードバック → 次のステップ更新提案
テーマに反映 → また今日に組み込む  ← ループ
```

---

## 各要素の仕様

### 1. Inbox

日常的な思いつきの受け皿。整理は後回し、投げ込みやすさが最優先。

- テキスト入力のみ。素早く投げ込める
- 複数のInboxエントリをまとめて1テーマにできる
- 1エントリを複数のテーマに分解することもできる
- AI対話を経てテーマに変換される（バッチ処理。まとめて整理）
- テーマ化されたエントリはアーカイブ（削除ではなく参照可能に残す）

### 2. テーマ

個人プロジェクト・興味領域を表す単位。数に上限はない。

**構成要素：**
- タイトル
- ゴール（AI対話から生成・編集可）
- 重さ（軽 / 中 / 重）
- ステップ（少数。3〜5個が目安）
- ステータス（アクティブ / アーカイブ）

**重さの定義：**

| 重さ | 意味 | 例 |
|---|---|---|
| 軽 | 1日で終わる | 本を1冊読む、レシピを試す |
| 中 | 完成形・終わりが見えている | アプリのMVPを作る、語学検定に合格する |
| 重 | 終わりが見えない、ずっと取り組む | 健康的な習慣を続ける、技術を深める |

**テーマのライフサイクル：**
- 目的を満たしたとき、または興味が薄れたときにアーカイブできる
- 完了・失敗の概念はなく、「閉じた」という状態
- アーカイブしたテーマは一覧から消えるが参照・復元できる

**テーマの絞り込み：**
- テーマ自体はいくつ作ってもよい
- 同時進行が増えると進まなくなる。AIコーチングで「今進めたいもの」を絞る
- AIが「しばらく触れていないテーマ」や「多すぎる状態」に気づかせる

**ステップの設計思想：**
- タスクを大量に並べない。意味のないTODOリストは着手しなくなる
- 「次にやること」が数個あれば十分
- AIフィードバックを経て継続的に更新・入れ替えされるもの

### 3. ステップ

テーマに紐づく具体的な行動単位。

**構成要素：**
- タイトル（具体的な行動として書く）
- 重さ（軽：〜15分 / 中：〜1時間 / 重：腰を据えてやる）
- ステータス（pending / 今日やる / アーカイブ）

**ステップのライフサイクル：**
```
pending → 今日やる（時刻・通知設定あり）
  ├→ 着手した → 「着手した」が記録される。ステップは残る → 翌日へ持ち越し
  └→ 完了 → アーカイブ（テーマのステップ一覧から消える）
```

- 「着手したが完了しなかった」はポジティブな記録として残す。自動削除しない
- 翌日に持ち越されたステップは再度時刻・通知を設定して使う
- テーマに残るステップは「まだやっていないこと」のみ

### 4. 今日やること

AIが今日のステップ候補を提案し、ユーザーが承認・調整するビュー。

**準備フロー：**
- 毎朝（または前日夜）にAIがアクティブなテーマのステップから候補を提案
- ユーザーはポチポチ承認/入れ替えするだけ。ゼロから選ぶ必要なし
- AIが提案できない・うまくない場合はユーザーが手動で追加できる

**時間・通知設定：**
- 各ステップに開始時刻・所要時間（分単位）を任意設定できる
- 設定した時刻に通知を受け取れる（着手を促す）
- 時刻未設定のまま「今日やること」に入れることも可能

**タイムライン表示：**
- 時刻設定済みのステップ → タイムライン上にブロックとして配置
- 時刻未設定のステップ → タイムライン外のリストに並ぶ
- 一覧ではステップタイトルを大きく表示。詳細（テーマ名・ゴール）はタップで展開
- 翌日切り替えタブあり（前日夜に翌日の準備ができる）

**操作：**
- 着手したらマーク（これが主操作）
- 完了した場合は完了マーク（着手マークと同一操作か選択）
- 内容の詳細判断は振り返り画面で行う

### 5. 振り返り

1日の終わりに今日のステップを3択でポチポチ評価し、AIが次を更新する。

**操作フロー：**
1. 今日スケジュールされたステップが一覧表示
2. 各ステップを3択で評価：`できた` / `着手した` / `できなかった`
3. 任意でメモを追加（一言でよい）
4. AIが評価を受け取り、一言フィードバック＋次のステップ更新提案
5. 提案されたステップをワンタップでテーマへ追加 or 却下

**振り返りの位置づけ：**
- 任意だが推奨（やらないと次のステップが更新されず前に進まない）
- 完璧にやる必要はない。ポチポチするだけで最低限の記録ができる
- AIはここで「着手できている」「テーマが前進している」ことを確認・言語化してくれる

### 6. AI の4つの役割

| タイミング | 役割 | 入力 | 出力 |
|---|---|---|---|
| 不定期 | Inbox → テーマ化 | 複数のInboxエントリ | テーマ（タイトル・ゴール・最初のステップ） |
| 毎朝 | 今日の候補提案 | アクティブなテーマ・ステップ一覧 | 今日やるステップ候補（承認/調整用） |
| 毎晩 | 振り返り＋次ステップ更新 | 3択評価・メモ | 一言FB・次のステップ更新提案 |
| 随時 | テーマ絞り込みコーチング | テーマ一覧・最終更新日 | 「今これに集中しては」という提案 |

## 画面構成

| 画面 | 役割 |
|---|---|
| 今日やること | 起動時のデフォルト画面。AI提案の承認・タイムライン・着手マーク |

## データモデル（概要）

```
InboxEntry
  - id
  - text
  - createdAt
  - status: active | archived
  - themeId?: (アーカイブ時にテーマへの参照を持つ)

Theme
  - id
  - title
  - goal
  - weight: light | medium | heavy
  - status: active | archived
  - createdAt
  - archivedAt?

Step
  - id
  - themeId
  - title
  - weight: light | medium | heavy
  - status: pending | today | archived
  - createdAt
  - archivedAt?

ScheduledStep（今日・翌日の計画）
  - id
  - stepId
  - date
  - startTime?        (開始時刻。分単位。未設定可)
  - durationMinutes?  (所要時間。分単位。未設定可)
  - notificationEnabled: boolean
  - started: boolean       (着手した。ステップは残る)
  - done: boolean          (完了。ステップはアーカイブ)
  - result?: できた | 着手した | できなかった  (振り返り時に記録)
  - memo?
  - actualStartedAt?
  - actualEndedAt?

CoachingMessage
  - id
  - contextType: inbox_batch | morning_suggest | review | theme_focus
  - contextId
  - role: user | assistant
  - content
  - createdAt
```

## 価値観・設計方針

- **着手ファースト**：完了できなくてもいい。始めることが目標
- **AIが候補を出す**：ゼロから考えさせない。承認するだけにする
- **ゆるく続ける**：完璧なレビューより、続けられる軽さを優先
- **テーマが前進している実感**：小さな着手の積み重ねをAIが言語化する
- **リストを増やさない**：たくさん並べると着手しなくなる
- **データはユーザーのもの**：ローカルファースト

## アーキテクチャ方針

- Kotlin + Jetpack Compose（Android のみ）
- 単一 app モジュール（当面）
- Room による SQLite ローカルストレージ
- ViewModel + StateFlow による状態管理
- AI は Claude API（APIキーはユーザーが設定）
- 通知は Android NotificationManager + AlarmManager

---

## 実装ロードマップ

1. **Inbox + テーマ一覧**：アイデア投入 → テーマ手動作成が動く状態
2. **ステップ管理 + 今日やること**：ステップを今日に引っ張り、着手・完了マーク
3. **振り返り**：3択評価 → 記録。AI なしでも機能する最小形
4. **通知**：着手を促すリマインド
5. **AI立ち上げ対話**：Inbox バッチ → AI対話 → テーマ自動生成
6. **AI朝の候補提案**：テーマ・ステップ一覧から今日の候補を提案
7. **AI振り返り対話**：3択評価 → AI一言FB → 次のステップ更新提案
8. **AIテーマ絞り込み**：多すぎるテーマへの気づき・フォーカス提案
